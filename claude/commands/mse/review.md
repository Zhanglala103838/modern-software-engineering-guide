---
description: 按工程规范 review 当前改动或指定 PR(试金石 + Reviewer 清单)
argument-hint: "[可选:PR 号 / 提交范围,默认未提交改动]"
---

先调用 skill `engineering-standards`(加载 Review 规范与两块试金石)。

审查范围:`$ARGUMENTS` 指定则用之(PR 号 → `gh pr diff`;提交范围 → `git diff`);否则审当前未提交改动(`git diff` + `git diff --cached`)。

按 SPEC 第四部分 Reviewer 清单逐维度过一遍,输出:
- **A 学习/反馈**:有无覆盖行为+边界的测试?增量可独立验证?
- **B 复杂度**:职责内聚?业务逻辑与框架/IO/DB 分离?耦合必要?抽象不过度/不投机?
- **C 两块试金石**:难测吗(难测→标记设计问题)?能独立部署/回滚?迁移向后兼容?密钥未入源码?
- **D 可读性与证据**:半年后读得懂?关键边界有 inline 注释?性能/安全断言有数据支撑?
- 命中第七/九/十部分场景(架构守卫/共享数据/安全)时一并查。

每条发现**区分 must-fix 与 nit(建议)**,给理由+替代方案,对事不对人。先按项目段位调强度(棕地别用绿地标准)。只读,不改代码。
